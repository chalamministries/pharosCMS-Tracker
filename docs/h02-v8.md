# H02 V8 positions

H02 TCP 5013 accepts V8 position reports as well as V1/V4. The common fields
contain the transmitted device ID, UTC time/date, validity, coordinates, speed
(knots converted to km/h), course and status word. Longitude may omit leading
zeroes, including values below one degree. TCP buffering remains handled by the
existing gateway: an incomplete frame consumes no bytes, and concatenated
frames are consumed one at a time.

V8 extension fields after the status word are retained as `h02_io1`, `h02_io2`,
etc. Their meaning varies by firmware. They are not treated as the older V1
optional voltage/IO/altitude layout. No battery percentage is inferred from an
unverified extension. This change does not modify the existing V1 sensor layout,
device configuration, relay, ports or historical records.

Routario's **Low Battery Alert > Voltage Sensor** setting chooses a decoded
sensor key such as `battery_voltage` or `external_voltage`; it does not map a raw
packet column into a battery reading. The current dashboard renders decoded
sensors. A firmware-specific decoder mapping is needed if a tracker reports its
battery in a different field. Voltage and percentage are different quantities.

Reference: [Traccar H02 decoder tests](https://github.com/traccar/traccar/blob/master/src/test/java/org/traccar/protocol/H02ProtocolDecoderTest.java)
include V8 packets with this common layout and unpadded longitude.
